距离度量及其计算——低维欧氏距离

2026-05-04

引入：欧氏距离与维数灾难

格点离散化技术

核心思想：画格子，找代表
将空间划分为许多的小方格，将同一个方格内这些距离相近的点以格子正中心点做代表，合并成一个点看待，在允许误差的情况下有效减少点的数量

直接以题目为例子进行说明

例题：近似求欧氏点集直径

题目链接：http://cssyb.openjudge.cn/26hw11/1/

题目描述

描述

在二维平面上有一个包含 n 个点的点集，你需要估计这个点集的直径，即最远点对的距离。

你需要保证你的输出与正确答案的相对误差不超过 10%，即设正确答案为 ans，你的输出为 out 需要满足 |ans-out| / ans <= 0.1.

输入

输入数据的第一行为一个正整数 n <= 10^5，表示点集大小。
接下来 n 行，每行两个绝对值不超过 10^9 的实数（小数点后至多有6位），表示一个点的坐标。

输出

输出一个实数，表示直径的大小。

思路分析

根据n的数据范围，显然不能用$ O(n ^ 2) $ 暴力扫描，考虑用格点离散化技术减少点数

设方格的边长为$l$，则对角线长度为 $ \sqrt{2} l$，将方格中的所有点强制合并到中心，移动的距离不超过对角线的一半；故我们需要 $(1 + \epsilon) $ 近似直径，只需要满足 $ \sqrt{2}l \leq \epsilon T$ 即可，故最终方格数只与 $ \epsilon $有关

事实上，为了方便实现，将方格内所有点合并到方格中任一点均可，比如均映射到方格左下角

主要分为三步骤：

  1. 对点集的直径进行估计，任取一个点，计算它到其它点的最大距离，就可以得到直径T的2-近似
  2. 预处理所有的点，将其合并到格子的右上角 将点集从$P$ 变换到$P’$
    • 本题为二维平面，容易想到利用类似桶排序的方法标记每个方格中是否有点；但是如果维数d达到5以上，方格个数将会大于点的个数，算法反而更差，且耗费大量空间
    • 所以我们考虑直接先将点的坐标各分量除以$l$并向上取整，（映射到方格右上角），然后逐个分量排序，复杂度 $O(nlogn)$，映射到一个方格的将会是连续的一段，然后进行去重，获得新的点集$P’$
  3. 直接扫描新的小点集$P’$，计算直径 复杂度 $O((\frac{1}{\epsilon}) ^ 2) $

实则是一道思路直接，代码实现容易的题目

四分树技术

基本思想：同样是“方格化”处理，假设所有点都在一个大方格里，在二维情况下，通常会将一个大方格划分成四个小方格，递归将当前方格划分成四个小方格，组织成树形结构；搜索的时候在树上逐层深入搜索

例题：（1+eps）欧式近似最近点查询

题目描述

描述

给出 n 个二维平面上的数据点 P = { (x1, y1), (x2, y2), … , (xn, yn) } 。

你的程序需要回答 q 次询问，每次询问给出一个二维平面上的点 (ai, bi) ，询问集合 P 中距离 (ai, bi) 最近的数据点。

假设集合 P 中距离 (ai, bi) 最近的数据点到 (ai, bi) 的距离为 d((ai, bi), P) ，你需要输出一个 [1,n] 中的整数 Ji ，使得 d((ai, bi), (xJi, yJi)) <= 1.15 * d((ai, bi), P) 。

保证查询点到最近数据点的距离如果非零，则至少是 1。

输入

第一行一个整数 n,q (1 <= n,q <= 10^5) 。
接下来的 n 行，每行两个浮点数 x_i,y_i (0 <= x_i,y_i <= 10^6) 。
接下来的 q 行，每行两个浮点数 a_i,b_i (0 <= a_i,b_i <= 10^6) 。

输出

对于每组询问，你需要输出一行一个整数 J_i ，表示 P 中距离 (a_i,b_i) 近似最近的点的下标。
